## 3. 既知の問題・注意点
1. **役のバランス（すべて初期値）**: 80試合の出現率（全席・全局あたり）で、能天気 98%、手広く営業 92%、第一印象 58%、虫歯 55%、階級社会 46% と、小役の一部はほぼ毎局成立します。点数は小さいものの、「結果で初めて発見できる楽しさ」の観点で条件・点数の調整が必要です（`roles.json` の `value` で変更可）。
2. **出にくい役**: 80試合で一度も出なかった役 — ダブル立直、槍槓、チャンタ、純チャン、三槓子、三色同刻、小三元、清一色、四暗刻ほか役満の多く、スーパージャックポット、アホ、スリーセブン、独占、キースーシー、ぐースーシー、ご近所付き合い、無駄のない無駄、お断りします、自力でお願いします、やっぱり自分で、原点回帰、四季折々。判定はすべてテスト済み。CPUがこれらを狙わないこと・CPUがあがりを見送らないことが主因です（お断りします等はプレイヤーが見送れば成立します）。
3. **役満テンパイ配牌キャラが強い**: s01_01 / s07_02 は毎局国士13面テンパイで始まるため、80試合で国士無双が49回出ています。`game_config.json` の `yakumanTenpaiStartChance`（初期1.0）で頻度を下げられます。
4. **CPUの思考は簡易**: シャンテン数・受け入れ枚数・危険度（リーチ者の現物）・役の見込みで判断。リーチ率が高め（席・局あたり約55%）。ジャックポットや新役を狙う評価、役満目前の見送りは未実装（評価関数の入口は `js/cpu.js`）。
5. **暗槓への国士の槍槓**は未対応（加槓の槍槓のみ）。
6. **画像の拡大方式**: 仕様の「ドット絵は pixelated」に対し、素材がすべて表示サイズより大きいため、縮小時に pixelated だと牌の線が抜けて「三萬」が「二萬」に見えました。縮小は滑らか補間、等倍以上に拡大する大画面のときだけ背景を pixelated にしています。
7. **保存はブラウザ単位**: localStorage は「ブラウザ＋アドレス（ポート番号含む）」ごと。`start.command` は8765番が使用中なら次の番号を使うため、その場合は別データになります。JSON書き出し/読み込みで移せます。

## 4. 仕様を閉じるために決めたこと（初期案・変更可）
仕様書の初期案（８局連荘なし、開始0点、供託なし、赤ドラなし、喰いタン・後付けあり、ロン換算満額加算、新役満32,000点、通常役満は１つ分を上限、途中流局なし、精算は和了順→未和了者の席順、自分の顔 s01_04）はそのまま採用。そのうえで以下を補いました。
- リーチ宣言牌でロンされても（失点が無いので）リーチは成立扱い。
- 一時フリテンは「和了形になる牌を見送った」とき（役が無くてロンできなかった場合も含む、通常ルールどおり）。自分の次のツモで解除。
- 加槓が槍槓された場合、その牌は宣言者の捨て牌履歴に入り、槓は成立しない。宣言者は次の人へ手番を渡す。
- 「一匹目の魚」の「鳴く」はチー・ポン・明槓。暗槓は含めない。「無口な人」も暗槓は鳴きに数えない。
- 「ニコニコ」の対子は２枚ちょうど（「三つの相棒」と同じく刻子から取り出さない）。
- 通常役満がある和了では、他の翻役は表示するが点数に足さない。ジャックポットでも同様（二重取りなし）。
- 数え役満（13翻以上）は役満相当の満額。親の役満は48,000点。
- 役満リーチは、通常役満のテンパイ、ジャックポットのあと１枚、振り込みの天才のあと１人、スリーセブン・独占のあと１枚で表示。CPUの場合も表示。
- 対局中は和了者の手牌を伏せたまま（仕様の初期案）。精算で開示。
- （v002）精算はクリックでのみ進む。
- VS画面で自分の顔の下に「あなた」と表示（キャラ名ではない）。
