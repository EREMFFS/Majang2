# 保存・役判定・CPU

## 状態分離
RuleEngine（牌・合法手・勝者確定）/ RoleEvaluator（標準・新役・小役）/ Scorer / CPU / Presentation / SaveStoreを分ける。
UIのアニメーション完了コールバックが配牌や得点計算を２回実行する構造にしない。
役はconditionIdで関数レジストリを呼ぶ。同じtile_min_counts等を役ごとに別実装しない。
JSONの日本語条件も読み、意図を推測したまま異なる判定を実装しない。

## 牌と根拠
TileInstance={id,kind}。kindはm1..m9,p1..p9,s1..s9,z1..z7。ドラの赤５画像は任意素材のみ、初期版では使わない。
PlayerRoundState={handIds,melds,discards,winSnapshot,riichi,furiten,active,initialHandIds,everTenpai,everNoten,...}。
Meld={type,tileIds,fromSeat,calledTileId,turn}。河の見た目から消えた牌もdiscards履歴から消さない。
Event={id,roundId,seq,seat,type,tileId,kind,targetSeats,sourceSeat,waitSetBefore,waitSetAfter,...}。
初期配牌直後に13枚手のテンパイ/ノーテンを記録。以後も打牌後など同じ状態境界で記録。
一時的な14枚取得中の状態を「一度ノーテンだった」等のカウントに混ぜない。

## 必須履歴
DEAL,DRAW,DISCARD,CHI,PON,ANKAN,MINKAN,KAKAN,RIICHI_DECLARED,LEGAL_RON_OFFER,DECLINE_RON,LEGAL_TSUMO_OFFER,DECLINE_TSUMO,WIN_RON,WIN_TSUMO,TENPAI_STATE,ROUND_END。
通常ツモ/嶺上を区別。各人の自分のツモ連番、打牌連番を持つ。
戻りツモ・隣の数字の連続判定は「自分の通常ツモ」の系列で行い、他家の番を間に挟んでも途切れない。
鳴いて自分が打牌した場合も直前の自分の捨て牌を更新。戻りツモの３連続は同じ牌種のまま継続したものだけ。
ノーテンからテンパイへの推移、待ち集合の変更は集合として比較。順序の違いを変化として数えない。

## 役判定の返り値
RoleAward={roleId,han?,fixedPoints?,minorPoints?,yakuman?,evidence:{kind,tileInstanceIds?,meldIds?,eventIds?,targetSeats?,turns?},sourceSnapshotId}。
同じ牌を異なる役へ利用可。ひとつの役の中で必要枚数の同じ牌を二重利用しない。
contains_same_suit_numbersは１つの数牌種ですべての必要枚数がそろうこと。m1+p2+s3はワンツースリーではない。
所有牌はその人の手牌＋自分の副露。捨て牌を手牌の役へ混ぜない。捨て牌役だけdiscards履歴を見る。
同役は１人１局１回。複数色で123を持っていてもワンツースリーを３回加点しない。
排他グループはhan/fixed/minorの単純数値比較ではなく、役ごとの優先度表で解決。戻りツモはアホ＞おかえり。
鳴きのジョーとスーポンツは別系列として併存する初期案。調整できるよう役データで管理。

## セーブ
schemaVersion,saveId,matchId,roundId,seed,rngState,stageId,playerFaceId,roster,seatOrder,roundIndex,cumulativeScores,physicalTileState,players,eventLog,jackpotTargets,pendingDecision,pendingSettlement,presentationCursorを保持。
牌山と乱数状態を保存し、ロード後に再配牌・再抽選しない。
精算IDごとにappliedフラグを持ち、演出途中から戻っても点数・役図鑑・戦績を重複加算しない。
戦歴はoverall,byCharacter,byRole。キャラIDをキーにし、キャラ名は不要。
途中で中断しても試合終了扱いの勝敗を付けない。完了した局の発見・獲得記録だけは保持する初期案。
保存JSONにはパスではなくIDを保存。素材のフォルダを変更しても戦績が壊れないようにする。

## CPU
全CPUが合法な手のみを選ぶ。能力差はシャンテン、受け入れ、危険度、役の期待点、見送りの評価、打牌ランダム度で表現。
基本はstandard,fast,closed,calling,big_hand,defensive等の傾向。未指定キャラに物語上の能力をでっち上げない。
strengthRankはステージ内の相対順位。具体的な絶対難易度は設定に分ける。
初期版の推奨マッピング: strongest=5,weakest=1を順位で滑らかに補間。弱いCPUにも少量のランダム性を入れる。
鳴きのジョー、振り込みの天才等の狙いを後付けできる評価関数の入口を作る。
初期版から、役満が目前ならあがりを見送る戦略も候補にできる。ただし全CPUが毎回それだけを狙うようにしない。
CPUの役知識はプレイヤー図鑑の開放状態と無関係。CPUが知っていることを対局中のUIでネタバレしない。
